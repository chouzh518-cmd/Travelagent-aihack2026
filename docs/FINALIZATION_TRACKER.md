# 最终版本收尾清单

更新日期：2026-09-22

本文记录当前发现的问题、主解决方案和备用处理方式。备用方案必须让员工能够继续安全地完成工作，或明确停止并说明可采取的人工步骤；模拟结果不能冒充真实数据。

## 本轮已处理

| 问题 | 主解决方案 | 备用方案 | 状态 |
| --- | --- | --- | --- |
| 差旅日期、人数、住宿等条件缺失时仍生成计划 | 先用明确标注的模擬默认值生成计划书，再在计划书页显示缺少字段和追加输入框；补充后可直接重新生成 | 服务不可用时保留模擬草稿并要求人工补齐关键条件；不把模擬值当作真实报价 | 已实现 |
| 条件抽取请求失败后静默沿用旧项目字段 | 抽取失败时停止计划生成并显示错误 | 检查连接后重试；用户输入仍保留，可修改后再次提交 | 已实现 |
| 切换项目后仍携带前一项目的上传资料引用 | 切换项目时清空当前会话上传引用和上传状态 | 需要使用资料时，在新项目会话重新上传 | 已实现 |
| 后端收到未经用户确认的 `confirmed=true` | 生成前展示登记条件和会话内容，由员工确认后才继续调用模拟报价 | 员工取消后可返回修改条件，再次发起生成 | 已实现 |
| “不要住宿”等否定表达被住宿关键词误判 | 本地解析器优先识别中文和日文的明确住宿否定，再识别住宿关键词 | 未命中的表达保持未确认；员工用“宿泊が必要／不要”明确补充后重试 | 已实现并完成直接验证 |
| 上传资料可能未在计划书中体现 | 当前资料会进入聊天和 `/api/run` 的检索范围，并在上传状态中提示；计划书正文不显示资料清单，避免增加内部信息 | 通过会话引用资料原文，由员工确认后补充条件；无法引用时查看原文件并手动补充 | 已实现范围绑定和人工确认路径 |
| 计划书绕过服务端行程、费用和规程检查 | 生成时调用 `/api/run`，并把当前项目及上传资料的确切文档和快照范围传给服务端；计划书显示检查结果 | `/api/run` 失败时保留标记为模拟的计划草稿，明确说明服务端检查未完成并要求恢复后重试 | 已实现，已完成本地端到端接口验证 |
| 语义搜索会把任意问题的最近区块当作证据 | 增加 FastEmbed 距离阈值 `0.75`；超过阈值时返回 `not_found`，不生成证据 | 调整问题表述、补充资料或人工查看原文；检索不到不表示规程不存在 | 已实现并通过“完全不存在关键词”测试 |
| 规程检索只返回证据，计划书无法显示已抽取的明确条款 | 仅从检索到的原文区块和关联表格抽取住宿上限及超额住宿审批条款，并保留位置和正文哈希 | 未识别条款时仍返回原文证据和人工复核提示，不自动判定合规 | 已实现并通过规则/API测试 |
| 快照 ID 可被随意写入路径或索引 | `chunk_blocks` 要求 64 位小写十六进制快照摘要 | 无法提供合法快照 ID 时停止导入，不生成不受约束的区块 | 已实现并通过测试 |
| 运行记录或草稿可能被 Git 收集 | 忽略 `output/runs/` 和 `output/drafts/` | 提交前检查 Git 状态；发现已跟踪的运行文件时先确认其历史清理方式 | 已实现忽略规则；历史状态待检查 |
| 同名上传文件可能复用同一个文档标识 | 上传文档 ID 由文件名和内容摘要共同生成；同名不同内容得到不同 ID | 上传失败时不使用旧资料；员工重新上传并确认当前资料名称和内容 | 已实现，并验证同名不同内容生成不同 ID |
| 公网接口没有请求频率保护 | 对登录和处理接口按客户端地址及路径做 60 秒窗口限流，超过后返回 429 和 Retry-After | 员工等待后重试；模型或实时服务不可用时继续使用规则解析、本地模拟和邮件模板 | 已实现，并验证第 31 次请求被限制 |
| 页面没有使用已有的资料删除接口 | 上传资料旁提供日语“削除”操作，删除快照、索引和当前会话引用 | 删除失败时保留本地引用并显示重试提示；切换项目时仍只清除当前引用，不误删资料 | 已实现并完成上传→删除接口验证 |
| 内部资料文件名出现在员工页面 | 资料卡片只显示登记标题和日语资料类型；项目 API 不再向浏览器返回仓库路径 | 需要定位文件时由受控维护人员查看目录，不把内部路径加入员工界面 | 已实现并验证项目响应不含 `path` |
| 计划书和咨询、邮件内容挤在同一页面，生成失败时原因不清楚 | 改为三步页面：相談 → 計画書 → メール；计划书生成成功后自动进入第 2 页，缺少条件时列出具体字段和下一步 | 服务不可用时保留本地模擬计划书，并明确提示重新生成；外部邮件仍只生成草稿 | 已实现并通过语法、全量回归和项目响应检查 |
| 原生确认框确认后看不到计划书，且“到着希望は 12:00”未被解析 | 使用网页内确认弹窗，确认后显示处理中并进入计划书页；解析器同时支持“12:00 到着”和“到着希望は 12:00” | 解析失败时保留相談页，列出缺少字段并要求补充后重试 | 已实现；自然语言样例已验证到着日時、帰着日時、人数和住宿状态可提取 |
| 计划书平滑滚动过程中被滚动监听器重置回相談页 | 只有检测到明确可见的页面时才更新当前步骤；滚动过渡期间保持目标页面状态 | 通过顶部步骤按钮或前后按钮重新进入目标页 | 已实现并通过 JavaScript 语法检查及 55/55 回归测试 |
| 删除接口可能误删内置登记资料 | 删除接口只接受当前 demo 绑定且 `document_id` 以 `upload_` 开头的资料；内置登记资料返回阻止结果 | 需要清理内置资料时由受控维护流程直接处理存储和绑定，不开放给页面 | 已实现并验证上传资料返回 200、内置资料返回 403 |
| Docker 部署排除整个 `data/` 导致项目目录缺失 | Docker 只排除 `data/policies`，项目目录保留在镜像；`APP_DATA_DIR` 缺少项目目录时回退读取代码目录，运行快照仍写入数据盘 | 嵌入模型或资料索引不可用时仍返回项目页面，聊天/检索显示明确降级提示，员工可手动输入条件 | 已实现代码路径和忽略规则；Docker 本机不可用，镜像构建未验证 |
| 生成的资料绑定文件可能被提交而与快照分离 | 将 `storage/bindings.json` 加入 Git 忽略；运行时绑定随数据目录维护 | 缺少快照时按未登记资料处理，重新导入或上传后再绑定 | 已实现忽略规则 |
| 交付信息分散在项目文档中 | 新增 `docs/RELEASE_READINESS.md`，集中记录启动、验证、降级和发布前人工确认项 | 以本地受限演示方式交接，未完成部署/身份/实时服务前不宣称生产可用 | 已实现 |
| 浏览器安全响应头不够完整 | 增加 `X-Frame-Options: DENY` 和 `Cross-Origin-Opener-Policy: same-origin`，与现有 CSP、nosniff 和 no-referrer 一起返回 | 不支持这些响应头的旧客户端仍由 CSP `frame-ancestors` 和主机/来源校验保护 | 已实现并通过 HTTP 测试 |
| 日程、天气风险没有进入计划书 | 计划生成时调用 `/api/travel-context`，当前使用可追溯的本地模擬日历和天气结果；恶劣天气在计划书底部以红色提示 | 未配置真实 API 时保留模擬结果、查询时间和“请出发前复核”提示；接口失败时仍生成计划草稿 | 已实现并通过大阪 2026-10-10 恶劣天气场景验证 |
| 条件文本中的“到着希望は…”被误识别为目的地 | 中文路线解析必须出现明确“从…到/前往”标记；日语时间条件不再污染项目已有的出发地和目的地 | 仍无法解析时保留项目字段，计划书列出未确认条件供补充 | 已实现并通过自然语言回归验证 |

## 仍需完成的功能与备用方案

| 问题 | 主解决方案 | 备用方案 | 完成条件 |
| --- | --- | --- | --- |
| 没有真实铁路、酒店、库存和当地交通数据源 | 在核实服务条款、价格、字段和凭据后实现独立适配器，并显示来源和查询时间 | 保留本地模拟器，持续标注“模擬”；没有实时报价时不做可购买性或真实总价结论 | 每类接入服务都有来源、查询时间、失败状态和字段校验；缺配置时可走模拟或停止 |
| 复杂度分流可能意外调用有费或自动路由 | `create_llm` 默认强制实际模型为 `orcarouter/free` | 只有明确设置 `ORCAROUTER_ALLOW_PAID=true` 才允许配置中的其他路由；免费请求被拒绝时使用规则解析和维护模板 | 已实现默认免费闸门；付费路由仍未实际验证 |
| 复杂度评分记录的路由与实际模型可能不一致 | 评分结果同时保留请求路由和实际路由；实际调用、追踪和降级均使用安全闸门后的路由 | 关闭付费权限时统一记录 `orcarouter/free`，不自动切换模型 | 已实现并验证默认实际路由为免费 |
| 模型服务可能不可用或拒绝免费请求 | 仅在服务端完成免费路由配置和成功验证后启用模型生成 | 使用本地规则抽取、检索原文和维护邮件模板；不声称模型已生成 | 配置缺失、429、超时和格式错误均有稳定降级文案，核心条件校验不依赖模型 |
| 计划书页面未使用完整后端工作流 | 统一由 `/api/run` 返回条件校验、规程证据、费用计算和阻塞原因 | 工作流不可用时，只展示清楚标记的模拟草稿，并禁止显示合规通过或有效报价排名 | 页面与下载文件使用同一结构化结果；阻塞和未确认项一致 |
| 规程资料是摘录，适用范围和审批细节不全 | 补齐经授权核实的完整制度及适用范围，再逐条引用原文证据 | 显示原文摘录和未确认事项，交由员工及审批者人工复核；系统不自动判定合规 | 每项结论可回到原文位置；证据不足时明确显示未判定 |
| 自然语言抽取可能误判否定、多时刻或日期关系 | 改进本地解析，并把结构化条件逐项展示给员工确认 | 无法确认时要求员工改写为单一日期、时间和明确是/否条件；不传入报价流程 | 解析结果有来源文本、确认状态和错误提示；矛盾输入会停止 |
| OCR 和文档抽取质量无法保证 | 对低置信度或部分抽取结果提供原文位置核对 | 员工查看原文件并在会话中手动补充关键条件 | 低置信度内容不会被当成已核实事实；原文可重新查看 |
| 上传资料没有组织、员工和项目级身份隔离 | 接入经批准的身份系统、权限模型、隔离存储与审计 | 只允许本地或受限演示环境，使用虚构和去敏资料，不开放生产资料 | 通过跨用户、跨项目访问审查；权限失败默认拒绝 |
| 远程部署和数据保留未验证 | 完成持久化、备份、删除期限、访问限速、密钥和部署配置审查 | 仅本地运行；远程访问未配置时保持关闭 | 部署检查、恢复演练和删除验证均有记录 |
| 邮件系统没有真实发送能力 | 在取得授权后接入企业邮件和审批系统，并保留发送前人工确认 | 提供可编辑、可复制的邮件草稿，员工在现有邮件客户端手动发送 | 草稿明确未发送；未配置时不显示发送成功 |
| 自动化测试及线上运行没有本轮证据 | 获得执行授权后运行现有测试并记录结果；部署后做健康检查和关键路径验证 | 在验证完成前将版本标为未验证，只作本地演示，不宣称生产可用 | 测试环境、结果、失败项和线上检查记录可复核 |
