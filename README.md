# 出張計画アシスタント

Python で構築した出張計画のデモアプリです。利用者は登録済みのプロジェクトを選び、行程条件を入力し、模擬プランや規程資料を確認したうえで、編集可能な計画書とメールの下書きを作成できます。

画面に表示する利用者向けの文言は日本語です。デモ資料や出力では「シミュレーション」「未確認」などを明示し、模擬交通・宿泊・天気・カレンダー情報を実際に照会した結果として扱いません。

> 本プロジェクトは、ルールベースの条件抽出、RAG 検索、モデルによる質問応答、決定的な検証、利用者の確認を組み合わせた出張計画支援ツールです。自律的に予約・承認・メール送信を行う本番用 Agent ではありません。

## プロジェクトの背景と目的

出張計画では、プロジェクトの背景、日程、場所、社内規程、費用情報を整理し、関係者と確認しながら案を作成する必要があります。情報が分散していると条件を見落としやすく、根拠となる資料と未確認事項も把握しにくくなります。

本プロジェクトでは、次のデモ工程を一つの画面で扱います。

1. 登録済みプロジェクトから業務背景を読み込みます。
2. 会話で行程条件を補足し、明示された内容を構造化された条件案へ反映します。
3. 登録資料やアップロード資料から規程の原文を検索し、引用と未確認事項を表示します。
4. 模擬プランの比較、条件検証、利用者によるプラン選択を行います。
5. 確認可能な計画書と、編集できるメールの下書きを作成します。

目的は「資料 → 条件 → 検証 → 人による選択 → 文書化」という追跡可能な流れを示すことです。企業の出張システム、経費承認、交通予約、人の判断を置き換えるものではありません。

### 想定する利用者

- 出張申請者：プロジェクトの選択、資料のアップロード、条件の補足、計画書の確認とプランの選択を行います。
- 承認者・管理者：整理された条件、資料根拠、メール下書きを確認し、既存の承認手続に沿って判断します。
- 保守担当者：リポジトリ内の公開可能なプロジェクト資料、依存関係、デプロイ用 Secret を管理します。プロジェクト資料を管理する画面はありません。

現在のデプロイでは、資料 API をチーム共有のアクセスパスワードで保護します。個々の社員・承認者・保守担当者を識別する権限モデルは実装されていません。

### 入力と出力

| 入力 | 出所 | 用途 |
| --- | --- | --- |
| プロジェクトの場所、目的、予算など | `data/projects/` の Markdown 資料 | 条件とプロジェクトコンテキストの初期化 |
| 旅費規程や補足説明 | プロジェクト資料、セッション中のアップロード | 原文根拠の検索。抽出内容は別途確認が必要 |
| 出発、到着、帰着、予算など | 利用者との会話、計画書の追加入力 | ローカルルールで抽出し、今回の条件案を更新 |
| 交通・宿泊プラン | 現在はローカル固定シミュレーター | ワークフローと比較のデモ。実際の見積りではありません |

| 出力 | 内容 | 外部操作の自動実行 |
| --- | --- | --- |
| 条件の状態 | 抽出済み項目、不足・未確認の条件、デモ上の仮定 | なし |
| 根拠と検証結果 | 原文の抜粋、引用箇所、サーバー側の検証状態 | なし。根拠の存在だけでは規程の適用を確定できません |
| 計画書 | 行程概要、プラン、費用、制約、要確認事項 | なし |
| メール下書き | 編集・コピー可能な日本語の文面 | 送信しません |

## エンドツーエンドの処理

### 1. プロジェクトと資料の読み込み

`GET /api/projects` は `data/projects/catalog.json` を読み、登録済み Markdown からプロジェクト項目と関連資料を読み込みます。項目は `project_catalog.py` に実装された日本語ラベルに基づいて取得し、任意の文章や大文字・小文字の違いから項目名を推測しません。プロジェクトを切り替えると、前のプロジェクトに紐づくセッション資料と計画書の状態を消去します。

アップロードファイルは `/api/import` から `PolicyStore` に渡されます。サーバーでファイルサイズと形式を検証し、テキスト抽出/OCR、内容スナップショットの保存、分割インデックスの作成を行い、資料を Demo 範囲に紐づけます。画面から削除できるのは現在のセッションでアップロードした資料のみで、登録済み資料はこの API から削除できません。

### 2. 会話と資料に基づく質問応答

フロントエンドは、現在のメッセージ、直近の会話履歴の一部、プロジェクトコンテキスト、今回アップロードした文書 ID を `/api/agent/chat` に送ります。`agents/rag_agent.py` は次の処理を行います。

1. リクエストの形式とプロジェクト ID を検証します。
2. プロジェクト ID とアップロード ID に基づいて検索対象を限定します。
3. 関連する資料の断片を検索します。信頼できる根拠が見つからない場合は、未検出または要確認の状態を返します。
4. モデルが設定されている場合、LlamaIndex の会話エンジンを通じて検索結果と会話コンテキストを OrcaRouter に渡します。
5. 回答と展開可能な引用情報を返します。規程に関する回答は、提示された引用に対応している必要があります。

自然言語モデルによる要約は表現の理解を助けるものであり、構造化された事実の情報源ではありません。日付、場所、予算、宿泊などはローカルのルールパーサーが抽出します。パーサーが認識しなかった内容を、モデルの推測で条件に書き込みません。

### 3. 追加質問と条件の更新

計画書の生成時、入力欄の内容を今回の条件としてユーザーメッセージに加え、`/api/intent/extract` でメッセージごとに解析します。解析された空でない場所、日付、時刻、予算、宿泊条件はプロジェクト項目の作業用コピーに反映され、後から明示された値が以前の値を上書きします。解釈できない表現によって既存値を自動消去することはありません。

パーサーが扱うのは定義済みの中国語・日本語表現であり、あらゆる自然言語の日付を理解するものではありません。日をまたぐ帰着、相対日付、複数の時刻、予算表現は、正式な手続に使う前に利用者が確認してください。計画書の仮定値はデモ用で、社員の確認済み条件を意味しません。人数は条件項目でもなく、模擬金額の計算にも使いません。

### 4. プランの生成、検証、選択

画面は今回の出張リクエストを構成し、次の API を呼び出します。

- `/api/simulation/offers`：交通・費用の候補をローカルで 2 件生成し、`data_kind=simulation` として識別します。
- `/api/travel-context`：ローカルの模擬天気・カレンダー情報を返します。
- `/api/run`：`core/planner.py` と `core/calculator.py` で行程と費用をサーバー側検証し、限定された資料範囲内で規程根拠を検索します。

検証結果は、不足データ、日付・行程上の問題、関連する規程原文を見つけるためのものです。検索結果だけで「規程に適合」とは判定せず、模擬見積りを実際に購入可能なプランとして順位付けすることもありません。計画書に候補を表示し、利用者が一つを明示的に選択した後にメール作成へ進めます。

### 5. 計画書とメール

計画書はブラウザー上で、ワークフロー結果、プロジェクト資料、利用者の入力、シミュレーターの応答を組み合わせて作成し、Markdown としてダウンロードできます。`/api/email/generate` はメール下書きを生成します。モデルが未設定または呼び出しに失敗した場合は、手動記入用のテンプレートを返します。本文は編集・コピーできますが、実際のメールアカウントや送信機能はありません。

## Agent、ルール、ツールの役割

| 機能 | 現在の実装 | 担当しないこと |
| --- | --- | --- |
| 会話 Agent | 対象を限定した資料検索、直近の会話に基づく回答と引用 | モデルの生成文を規程原文として扱うこと、構造化された行程項目の自動変更 |
| 複雑度評価・ルーティング | `agents/intent_router.py` が設定に基づいてリクエスト経路を選択 | タスクプランナーとしての判断、外部モデル呼び出しの成功保証 |
| 条件抽出 | `core/intent_parser.py` による説明可能なルール処理 | あらゆる表現への対応、常識による日付・予算・目的地の補完 |
| 資料検索 | `policy_import/`、Chroma/FastEmbed、`rag/` | 類似度だけによる資料の適用性・有効性の証明 |
| 業務計算・検証 | `core/calculator.py`、`core/planner.py` | 実運賃、在庫、予約、社内規程の最終解釈の確認 |
| 外部データ連携 | `tools/` の接続境界とローカル模擬プロバイダー | 航空、鉄道、ホテル、天気、カレンダー各社への接続済みとの保証 |
| 人による判断 | 条件確認、プラン選択、計画書のレビュー、メールのコピー | 承認者・経理・社員の判断や取り消せない操作の代行 |

Agent 関連の構成要素はありますが、エンドツーエンドの処理は決定的なアプリケーションコードが制御します。任意のツール連鎖を自律的に決定・実行したり、予約や承認メール送信を自動で行ったりはしません。

## 主な機能

- プロジェクト選択：`data/projects/catalog.json` からプロジェクトと Markdown 資料を読み込みます。サンプルの `planty` は架空のプロジェクトです。
- 資料取り込み：登録資料と、利用者がアップロードする PDF、DOCX、Markdown、画像に対応します。ローカルで抽出/OCR、分割、Chroma ベクトルインデックスを行います。
- 資料に基づく質問応答：許可された資料範囲で根拠を検索し、回答に引用を表示できます。OrcaRouter が未設定または利用できない場合は、画面に縮退動作を示します。
- 条件抽出：明示された場所、日付、時刻、予算、宿泊条件などをローカルルールで解析します。会話で追加した条件は作業用コピーを更新します。人数は収集・計算しません。
- プラン比較：模擬交通・費用プランを 2 件生成します。計画書でプランを選ぶとメール作成へ進めます。
- 業務検証：行程・費用の完全性、資料の範囲をサーバーで検証し、規程根拠を検索します。根拠不足や適用範囲が不明な場合は人による確認を求め、自動で適合判定しません。
- 計画書とメール：計画書および編集・コピー可能なメール下書きを作成します。予約、承認申請、メール送信は自動実行しません。
- セキュリティ境界：インターネット公開にはチームアクセスパスワードと正確な信頼済みホスト名が必要です。書き込み API では送信元検証とリクエスト制限を行います。

## 利用者の操作フロー

```text
プロジェクトを選択 / 資料をアップロード
        ↓
日本語の会話で出発・到着・帰着・予算などを補足
        ↓
条件を確認して計画書を生成
        ↓
模擬プラン、費用、規程根拠を確認してプランを選択
        ↓
編集可能なメール下書きを作成
```

計画書の生成では、ローカルの模擬プラン API、カレンダー・天気の模擬 API、サーバー側の `/api/run` 検証を呼び出します。模擬プランはリアルタイム見積りではなく、購入や実行可能性の証明には使えません。日付・時刻などが不足する場合、計画書には未確認事項やデモ用の仮定を表示します。

## 技術構成

| ディレクトリ / ファイル | 役割 |
| --- | --- |
| `app.py` | Python 標準ライブラリによる HTTP サーバー、静的ファイル/API ルーティング、入力検証、アクセス制御、レート制限 |
| `templates/` | HTML ページテンプレート |
| `static/` | 日本語フロントエンド、スタイル、ワークフロー操作 |
| `agents/` | 資料に基づく質問応答、意図の複雑度評価、モデルルーティング、メール下書き生成 |
| `core/` | 行程データモデル、自然言語のルール解析、決定的な費用・行程検証、ワークフロー |
| `policy_import/` | 資料抽出、OCR、資料スナップショット、ベクトル検索、出所の紐付け、根拠処理 |
| `rag/` | 制御された検索結果と LlamaIndex のアダプター |
| `llm/` | OrcaRouter/OpenAI 互換モデル接続と安全な縮退動作 |
| `tools/` | 交通、ホテル、天気、カレンダーなどの模擬ツール。未設定のサービスは利用不可と明示 |
| `data/projects/` | アプリとともに配布するプロジェクト一覧と、公開可能な Markdown 資料 |
| `data/offers/` | ローカル見積り入力のサンプル |
| `config/` | 資料取り込み、モデル複雑度ルーティング、サービス状態の設定 |
| `schemas/` | API/データモデルの JSON Schema |
| `tests/` | 単体テスト、業務フロー、HTTP API テスト |
| `docs/` | アーキテクチャ、プロジェクト資料登録、デモ、リリース確認に関する文書 |

モデルは検索資料に基づく自然言語の質問応答と下書き表現を担当します。日付・予算などの構造化条件はローカルパーサーが抽出し、金額計算と検証は Python のロジックで実行します。モデルは見積りツールや適合判断を代替しません。

## 動作環境

- Python 3.12（Docker イメージと同じバージョン）
- Windows PowerShell、macOS/Linux のシェルで実行できます。
- Node.js は任意です。フロントエンド JavaScript の構文確認に使用します。
- ローカルのセマンティック検索を初めて使う際に FastEmbed モデル（約 220 MB）をダウンロードします。
- OrcaRouter API Key は任意です。未設定でもルール解析、プロジェクト画面、利用可能なローカル模擬フローは動作します。モデルによる質問応答・生成は縮退動作になります。

依存関係のバージョンは [`requirements.txt`](requirements.txt) を参照してください。OCR、PDF、DOCX、ベクトル検索の依存関係はインストール容量と初回起動時間を増加させます。

## ローカルでの起動

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

### macOS / Linux

```bash
python3.12 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -r requirements.txt
./.venv/bin/python app.py
```

既定では `127.0.0.1:8765` のみで待ち受けます。起動後に <http://127.0.0.1:8765/> を開いてください。`/healthz` でヘルスチェックができます。

ローカル起動では既定でログインパスワードを要求しません。パスワードなしのローカルインスタンスをインターネットに公開しないでください。

### 任意：モデルサービスの有効化

起動するシェルで OrcaRouter Key を設定してください。Key をソースコードに記載したり、Git にコミットしたりしないでください。

PowerShell：

```powershell
$env:ORCAROUTER_API_KEY = "管理者から安全な方法で受け取った API Key"
$env:ORCAROUTER_MODEL = "orcarouter/free"
.\.venv\Scripts\python.exe app.py
```

macOS/Linux：

```bash
export ORCAROUTER_API_KEY='管理者から安全な方法で受け取った API Key'
export ORCAROUTER_MODEL='orcarouter/free'
./.venv/bin/python app.py
```

Key が未設定、無料ルートが拒否、レート制限、またはモデル応答形式が無効な場合、アプリは利用可能なルール解析やメールテンプレートへ縮退します。Key を設定しても、サービス事業者による利用許可や利用枠は保証されません。

## 設定項目

| 環境変数 | 既定値 / 要件 | 用途 |
| --- | --- | --- |
| `APP_BIND_HOST` | `127.0.0.1` | 待ち受けアドレス。インターネット公開時はアクセスパスワードと信頼済みホスト名も設定してください。 |
| `PORT` | `8765` | HTTP ポート。コンテナの既定値は `7860`、Render Blueprint では `10000` です。 |
| `APP_DATA_DIR` | リポジトリのルート | 実行時スナップショット、インデックス、紐付け、出力の保存先。デプロイ時は通常、永続ディスクのパスを設定します。 |
| `APP_ACCESS_PASSWORD` | インターネット公開時は必須 | チーム共有アクセスパスワード。公開 API は Bearer Token で検証し、ログイン画面のパスワードは現在のブラウザーセッションに保存します。 |
| `APP_TRUSTED_HOSTS` | 公開時に必要 | 許可する正確なホスト名をカンマ区切りで指定します。プロトコル、パス、ワイルドカードは指定しません。 |
| `RENDER_EXTERNAL_HOSTNAME` | Render が設定 | Render のホスト名検証に使用します。`APP_TRUSTED_HOSTS` と併用できます。 |
| `ORCAROUTER_API_KEY` | 任意 | OrcaRouter API Key。 |
| `ORCAROUTER_MODEL` | `orcarouter/free` | リクエスト先のモデルルート。既定では無料ルート用の安全制御が適用されます。 |
| `ORCAROUTER_ALLOW_PAID` | 未設定またはその他の値 | 組織の明示的な承認を得て `true` に設定した場合のみ、設定済みの有料ルートを許可します。既定では無効です。 |

インターネット公開時の設定例（変数名と安全上の要件のみを示します。実際のパスワードをコマンド履歴に記録しないでください）：

```text
APP_BIND_HOST=0.0.0.0
APP_ACCESS_PASSWORD=<プラットフォームの Secret 管理機能で設定>
APP_TRUSTED_HOSTS=<正確なホスト名>
APP_DATA_DIR=<永続データディレクトリ>
PORT=<プラットフォーム指定のポート>
```

アプリは Host/Origin を検証し、機密 API にアクセス Token を要求します。CSP、`X-Frame-Options`、`nosniff` などのセキュリティヘッダーも返します。ローカル Chroma ストレージは単一インスタンス向けです。共有ストレージとロック設計なしに複数インスタンスへ水平スケールしないでください。

## 実行時データとプライバシー

- アップロード内容、抽出テキスト、インデックス、資料の紐付け、ワークフロー記録、メール下書きは実行時データであり、Git に含めないでください。
- 既定の除外設定は `.env`、`data/policies/sources/`、`data/policies/snapshots/`、`storage/`、`output/` の一部を対象にします。コミット前に `git status` とステージ済みファイルを必ず確認してください。
- `data/projects/` はアプリに必要な配布資料です。デプロイ前に公開許可と匿名化を確認してください。
- 利用者の資料はローカルで OCR/抽出され、ローカルデータディレクトリに保存される場合があります。モデルが正常に設定されている場合、会話やメール生成に必要なコンテキストが OrcaRouter に送信されます。利用前に組織で利用規約と資料の取扱許可を確認してください。
- トレースログに API Key、会話全文、アップロード原文、メール宛先を保存しないでください。実行出力はデプロイ環境の保管期間に従って管理してください。
- 現在のアクセスパスワードはチーム共有です。企業 ID 管理、個人別権限、マルチテナント分離、完全な監査システムの代わりにはなりません。

## API 概要

主なインターフェースは `app.py` に実装され、Pydantic モデルで入力を検証します。未知のフィールドは拒否されます。

| メソッド | パス | 用途 |
| --- | --- | --- |
| `GET` | `/` | 日本語の社員向け画面 |
| `GET` | `/healthz` | ヘルスチェック |
| `GET` | `/api/projects` | 登録済みプロジェクトと資料 |
| `GET` | `/api/snapshots` | 現在の Demo 資料スナップショット |
| `GET` | `/api/agent/status` | 画面で使用する登録資料数の概要 |
| `GET` | `/api/plan-schema` | PlanInput JSON Schema のダウンロード |
| `POST` | `/api/login` | チームアクセスパスワードを検証し、現在のセッション Token を取得 |
| `POST` | `/api/agent/chat` | 許可された資料範囲で検索し、回答を生成 |
| `POST` | `/api/intent` | ローカル構造化抽出と、任意のモデルによる意図整理 |
| `POST` | `/api/intent/extract` | ローカルルールのみで構造化抽出 |
| `POST` | `/api/simulation/offers` | ローカルの模擬出張プランを生成 |


## デプロイ

### Hugging Face Spaces

リポジトリには Docker Space のメタデータがあります。コンテナは `0.0.0.0:7860` で待ち受けます。Space の設定で次を構成してください。

- 必須：`APP_ACCESS_PASSWORD`
- 必須：`APP_TRUSTED_HOSTS`。正確な `<ユーザー名>-<Space名>.hf.space` を指定
- 推奨：`APP_BIND_HOST=0.0.0.0`、`PORT=7860`、`APP_DATA_DIR=/var/data`
- 任意：`ORCAROUTER_API_KEY`、`ORCAROUTER_MODEL=orcarouter/free`

既定の一時ディスクは利用者のアップロード資料の長期保存には適しません。永続ストレージを構成していない場合は、匿名化したデモ用途に限ってください。

### Render

リポジトリには `render.yaml` と Dockerfile があります。Blueprint でデプロイする際は、プラットフォーム上で `APP_ACCESS_PASSWORD` と `ORCAROUTER_API_KEY` の Secret を設定してください。モデルを有効にしない場合も、任意 Secret の扱いをプラットフォーム上で確認してください。Render は `RENDER_EXTERNAL_HOSTNAME` を提供します。無料インスタンスはスリープし、一時ファイルが失われる可能性があるため、長期データ保管には使用しないでください。

プラットフォームの制約と公開前の確認事項は [`DEPLOY_HF_SPACES.md`](DEPLOY_HF_SPACES.md)、[`DEPLOY_RENDER.md`](DEPLOY_RENDER.md)、[`docs/RELEASE_READINESS.md`](docs/RELEASE_READINESS.md) を参照してください。Docker イメージとオンラインサービスは、対象プラットフォーム上で実際にビルド・デプロイ・検証する必要があります。この README はオンライン検証の完了を意味しません。

## 現在の制約

- 鉄道、航空、ホテル、座席在庫、現地交通、天気、カレンダー、メール送信などの本番用外部連携は構成されていません。画面上の関連サンプルは固定シミュレーターの場合があります。
- 模擬費用は実際の合計金額を保証しません。費用の欠落、日当の不明、宿泊費の仮定は未確認として表示します。
- ローカルのルールパーサーが対応するのは限定された明示的な中国語・日本語表現です。複雑、曖昧、矛盾する日付・時刻は利用者が確認してください。解析結果は利用者の確認を意味しません。
- RAG 検索結果は資料根拠の候補です。規程が現行であること、当該企業・社員に適用されること、経費精算が認められることを自動で証明しません。
- 計画書とメール下書きには人による確認が必要です。アプリは予約・承認・送信を自動実行しません。
- チーム共有パスワードと単一マシンのローカルストレージを使用します。本番環境に必要な企業 ID 管理、個人別認可、マルチテナント分離、バックアップ・復元、完全な監査機能はありません。
- OrcaRouter の利用可能なモデル、無料枠、利用資格、ネットワーク状態は外部サービスに依存します。モデルが利用できない場合は、表示される縮退動作に従ってください。
